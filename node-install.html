安装前准备

使用独立的 Ubuntu/Debian linux-amd64 服务器。建议至少 4 核 CPU、8 GiB 内存、100 GiB 存储，以及上下行各 100 Mbps；需要稳定公网 IPv4、正确的 DNS 和系统时间。

公网安全组端口

17880/tcpLiveKit TLS 信令
17881/tcpTURN over TLS
17882/udp · 17883/udp实时媒体与 TURN UDP
17884/tcp节点静态服务
18000–18100/udpRTC 媒体端口段

17879 为内部信令端口，不要对公网开放。节点不占用 80、443、8080 或 8443。

一键安装新节点

在服务器终端逐行执行。把区域和邮箱换成真实值；公网 IP 无法自动识别时追加 --public-ip 服务器公网IP。

curl --proto '=https' --tlsv1.2 -fL --retry 3 \
  -o install-gpc-node.sh \
  https://api.gpcchat.com/releases/livekit-node/install-gpc-node.sh
curl --proto '=https' --tlsv1.2 -fL --retry 3 \
  -o install-gpc-node.sh.sha256 \
  https://api.gpcchat.com/releases/livekit-node/install-gpc-node.sh.sha256
sha256sum -c install-gpc-node.sh.sha256
chmod 700 install-gpc-node.sh
./install-gpc-node.sh --version
sudo ./install-gpc-node.sh \
  --region cn-hangzhou \
  --acme-email your-email@example.com

校验必须显示 install-gpc-node.sh: OK；版本必须同时显示安装器 2026.09.06.3 和节点包 1.13.4-gpc.22。任一项不一致都应停止安装。

安装后校验

版本应为 1.13.4-gpc.22，状态应包含 READY 与 online=true，health 命令必须成功。首次签发证书和目录同步可能需要几分钟。

sudo gpc-livekit-node version
sudo gpc-livekit-node status
sudo gpc-livekit-node health
sudo gpc-livekit-node address

在 App 中认领节点

生成一次性二维码后，在 App 打开“设置 → 节点质押与收益 → 扫描节点认领二维码”。认领码 10 分钟失效且只能使用一次。运营者在 App 设置 10%–90% 的用户分成比例，并由身份钱包自行支付 BNB Gas。

sudo gpc-livekit-node claim

原服务器升级

先排空并确认 activeRooms=0、没有在线参与者，再执行升级。升级器会保留节点钱包、节点 ID、域名、配置、质押、委托和待领取收益；验证失败会恢复旧文件。

sudo gpc-livekit-node drain
sudo gpc-livekit-node status

curl --proto '=https' --tlsv1.2 -fLO \
  https://api.gpcchat.com/releases/livekit-node/1.13.4-gpc.22/GPC-LiveKit-Node-1.13.4-gpc.22-linux-amd64.tar.gz
curl --proto '=https' --tlsv1.2 -fLO \
  https://api.gpcchat.com/releases/livekit-node/1.13.4-gpc.22/SHA256SUMS.txt
sha256sum -c SHA256SUMS.txt
tar -xzf GPC-LiveKit-Node-1.13.4-gpc.22-linux-amd64.tar.gz
cd GPC-LiveKit-Node-1.13.4-gpc.22-linux-amd64
sudo ./upgrade.sh
sudo gpc-livekit-node resume

更换服务器并保留身份

旧服务器排空后，经加密受控渠道转移 /var/lib/gpc-livekit/node-wallet-key，并保持 0600 权限。新机安装成功后旧机令牌失效，新机需重新连续达标 24 小时。

sudo ./install-gpc-node.sh \
  --replace-node ORIGINAL_NODE_ID \
  --wallet-key-file /secure/path/node-wallet-key \
  --region ORIGINAL_REGION \
  --acme-email your-email@example.com

故障处理与安全底线

  • 不要把节点钱包私钥、节点令牌、完整配置或认领码发到聊天、工单或日志。
  • 只从本页 HTTPS 地址下载安装器；不要跳过 SHA-256 校验。
  • 节点不 READY 时先检查安全组、证书、系统时间、公网 IP，再运行 health、status、logs。
  • 升级提示繁忙时保持排空并等待房间归零，不要强制停止正在服务的会议或直播。
  • 不要通过反复重装掩盖故障，也不要删除 node-wallet-key。

常用诊断命令：sudo gpc-livekit-node health、status、logs。

GPC 服务节点不是区块链共识验证节点。质押与节点收益存在风险，请独立判断。
